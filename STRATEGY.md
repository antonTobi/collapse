The goal of the game is to maximize the score. The main way to do this is to extend the length of the game as long as possible. There is only a finite number of 6:s that can be made, so we should wait as long as possible before making the first 6. Similarly, while building up towards the first 6, we should wait as long as possible to make each 5. Etc. So a general heuristic is to prefer making smaller tiles first. However, for tiles smaller than 5 the ordering becomes less important (choosing between making a 2 and a 3 is more dominated by the resulting board position, it doesn't matter so much that 3 is greater than 2, but if all else is equal we still prefer the 2).

The game is lost when there are no chains with more than one tile, a sort of checkerboard pattern. A good heuristic is to maximize the number of legal moves. When doing lookahead there are two options: simulate multiple random outcomes, or treat generated tiles as 6:s. The former is more accurate but makes search much slower. The latter works surprisingly well based on some earlier tests (this form of lookahead is very pessimistic, and will not accurately predict the expected score, but is is quite good at finding the relative ordering of good moves).

There are also some more advanced heuristics:
- When building a chain of 5, try to keep all 5's connected. Making a disconnected 5 is risky (although optimal play will do this in cases where it is very likely that you will be able to connect it back soon).
- Place the first 6 in the corner. More generally, avoid placing 6's with 3 "open" spots arround it (at least 2 directions should be wall / other 6s). Dually, avoid creating (non-6) spaces that are surrounded on 3 sides by 6s / wall.
- In general it is bad to have low tiles in a low position on the board, and high tiles in high positions. Tile values naturally increase as we collapse and things move down, so it becomes easier to create matches if we keep high tiles towards the bottom and low tiles towards the top. (we have limited control of this course, but there are cases were we are choosing between two similar-looking moves, and one of them results in a 1 in an awkwardly low postion, for instance)

A note on legal move enumeration: if there are multiple tiles with the same value stacked on top of each other, there is no mechanical difference between which of them we collapse to. We can collapse such groups of multiple equivalent moves into a single canonical move by the following rule: a move is not legal if the tile directly below it has the same value. (this ensures that only the lowermost tile of a consecutive vertical chain of tiles becomes a legal move).
